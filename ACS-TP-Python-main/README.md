# Практическая работа №1 (СРВ, Python)
## Классификация систем реального времени и расчёт требуемого времени реакции

Консольное приложение на **Python 3.10+**, которое читает набор задач из **JSON** и выполняет классификацию/расчёты для системы реального времени: типы дедлайнов, запас времени, критическая задача, требуемое время реакции, коэффициент загрузки и архитектурный класс системы.

**Вариант:** *Узел АСУ ТП*.
**Выполнил:** *Марченко И.Р.*
---

---
## Возможности

Программа для набора задач рассчитывает и выводит:

- Класс системы по жёсткости:
  - **жёсткого реального времени**, если есть хотя бы одна *жёсткая* задача;
  - иначе — **мягкого реального времени**.
- Тип дедлайна каждой задачи по `D` и `T`:
  - **неявный** (`D = T`)
  - **ограниченный** (`D ≤ T`)
  - **произвольный** (`D > T`)
- Запас времени задачи: `L = D − C` и признак выполнимости (`L ≥ 0`)
- Критическую задачу (минимальный `L` среди **жёстких** задач)
- Требуемое время реакции системы: `R_треб = min(D)` по жёстким задачам  
  (если жёстких нет — по всем задачам)
- Коэффициент загрузки: `U = Σ(Ci / Ti)` и проверку необходимого условия `U ≤ 1`
- Архитектуру: **однопроцессорная / многопроцессорная / распределённая**  
  (при `has_network = true` → распределённая)

## Формат входных данных (JSON)
Файл содержит объект system и массив tasks.

system
n_cpu (int) — число процессоров
has_network (bool) — наличие сети
tasks[]
Каждая задача содержит:

name (str) — имя задачи
hardness (str) — класс жёсткости: жёсткое / твёрдое / мягкое
C (int) — время выполнения (мс)
D (int) — относительный дедлайн (мс)
T (int) — период (мс)
Файл читается в кодировке UTF-8.

Пример входного файла (вариант «Узел АСУ ТП»)
data/variant.json:

JSON
```Bash
{
  "system": {
    "n_cpu": 1,
    "has_network": true
  },
  "tasks": [
    {"name": "Приём телеметрии", "hardness": "жёсткое", "C": 3, "D": 20, "T": 20},
    {"name": "Контур регулирования (ПИД)", "hardness": "жёсткое", "C": 2, "D": 8, "T": 10},
    {"name": "Обмен по промышленной сети", "hardness": "твёрдое", "C": 5, "D": 40, "T": 50},
    {"name": "Самодиагностика", "hardness": "мягкое", "C": 10, "D": 150, "T": 200},
    {"name": "Архивация/журналирование", "hardness": "мягкое", "C": 30, "D": 1200, "T": 1000}
  ]
}
```
Пример вывода (sample output)
Фактический вид таблицы зависит от ширины консоли и длины названий задач, но структура такая:
```Bash
Задача                       | Класс   | C | D    | T    | L    | Выполнимо | Тип дедлайна
----------------------------+---------+---+------+------|------+----------+-------------------
Приём телеметрии            | жёсткое | 3 | 20   | 20   | 17   | да       | неявный (D=T)
Контур регулирования (ПИД)  | жёсткое | 2 | 8    | 10   | 6    | да       | ограниченный (D<=T)
```

Заключение:
- Класс системы: жёсткого реального времени
- Архитектура: распределённая (CPU=1, сеть=да)
- Критическая задача (среди жёстких): Контур регулирования (ПИД) (L=6 мс)
- Требуемое время реакции R_треб = 8 мс
- Коэффициент загрузки U = 0.5300; необходимое условие U<=1: выполнено
- Проверка дедлайнов по запасу (L>=0): все выполнимы


Примечания
Условие U ≤ 1 является необходимым, но не всегда достаточным для гарантии выполнения всех дедлайнов (в этой работе требуется именно проверка необходимого условия).
Критическая задача определяется только среди жёстких (если жёстких задач нет — критическая задача отсутствует).
